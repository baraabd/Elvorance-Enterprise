# التشغيل والترحيل والأسرار

## ملفات التشغيل

`infra/compose/compose.yaml` بيئة تطوير تضم 17 حاوية: سبع خدمات أعمال، وسبعة مهاجرين، وبوابة، وPostgreSQL 16، وRabbitMQ 4. لا يشمل الملف مزود هوية خارجيًا؛ يستخدم HS256 التطويري صراحة. انظر دليلي Windows وLinux للأوامر.

`infra/compose/compose.production.example.yaml` مرجع إنتاج مستقل يطلب صورًا مراجعة، وOIDC، وملفات أسرار. لا يُدمج فوق ملف التطوير؛ استيفاء متغيرات كل ملف يسبق الدمج، لذلك يفصل المرجع الإنتاجي عن إعدادات التطوير. لم يُنفذ هذا المرجع على مضيف إنتاج في بيئة إعداد الحزمة.

## بناء صورة مستقلة

أسماء الصور والحسابات التي تستخدم البادئة `atlas-` محفوظة مؤقتًا للتوافق مع ملفات Compose الموجودة؛ تحديث العلامة التجارية لا يغيّر هذه المعرّفات التشغيلية تلقائيًا.


```bash
docker build -f infra/docker/service.Dockerfile --build-arg SERVICE_NAME=sales -t atlas-sales:local .
```

يكون سياق Docker جذر Enterprise. تنفذ مرحلة البناء `npm ci` من lockfile ثم `build:services`. تنسخ مرحلة التشغيل حزمة Sales وحدها، دون مصادر أو حزم تشغيل الخدمات الأخرى. تضم الحزمة اعتماديات JavaScript؛ يبقى `pg-native` خيارًا غير مستخدم. تعمل بمستخدم `node`، ويضيف Compose نظام ملفات للقراءة فقط، و`no-new-privileges`، وإسقاط capabilities. تستخدم قاعدة البيانات والوسيط صورتيهما وآليات تهيئتهما؛ لا يطبق مستخدم Node عليهما.

يمكن تثبيت `NODE_IMAGE` بواسطة digest في CI. العلامات الافتراضية `node:24-bookworm-slim` و`postgres:16-bookworm` و`rabbitmq:4-management` قابلة للتغير؛ لا تكفي وحدها لادعاء تطابق صور Docker بايتًا ببايت عبر الزمن. الإصدار الموزع يثبت digests ويحتفظ ببصمات الحزم والاعتماديات ونتيجة البناء من نسخة نظيفة.

## تهيئة أسرار الإنتاج

انسخ `.env.production.example` إلى ملف بيئة محلي، واضبط صور الخدمات بدجست حقيقي وعنوان issuer وaudience وJWKS والأصول المسموحة. اجعل `SECRETS_DIR` مسارًا مطلقًا خارج مصادر بناء الحزمة. يحتاج المرجع الملفات التالية:

| اسم الملف                         | المحتوى                                  | من يقرأه                          |
| --------------------------------- | ---------------------------------------- | --------------------------------- |
| `postgres_admin_password`         | كلمة مرور حساب التهيئة                   | PostgreSQL فقط                    |
| `<service>_db_password` لكل نطاق  | كلمة مرور دور الخدمة                     | PostgreSQL عند تهيئة volume جديدة |
| `<service>_database_url` لكل نطاق | URI القاعدة والدور وكلمة المرور المطابقة | الخدمة ومهاجرها فقط               |
| `rabbitmq_password`               | كلمة مرور المستخدم المهيأ للوسيط         | RabbitMQ فقط                      |
| `rabbitmq_url`                    | URI الخاص بالـvhost وبيانات الاتصال      | خدمات الأحداث ومهاجروها           |

مثال شكلي، دون بيانات اتصال فعلية:

```text
postgresql://atlas_sales:<URL_ENCODED_PASSWORD>@postgres:5432/atlas_sales
amqp://atlas:<URL_ENCODED_PASSWORD>@rabbitmq:5672/atlas
```

يجب أن تتطابق كلمة المرور في ملف اتصال الخدمة مع كلمة مرور دورها. يقرأ entrypoint ملفات `DATABASE_URL_FILE` و`RABBITMQ_URL_FILE` دون طباعة القيم. تحتاج ملفات Compose secrets على المضيف إلى صلاحيات مناسبة ونسخ احتياطي آمن، ويمكن توريدها من مدير أسرار. لا تُضمّن في image أو Git أو إعدادات الواجهة. البوابة معزولة عن شبكة البيانات ولا تحصل على `DATABASE_URL`.

```bash
docker compose --env-file infra/compose/.env.production -f infra/compose/compose.production.example.yaml config --quiet
```

بعد اعتماد الإعدادات ونجاح بوابات الإصدار يمكن للمشغل تشغيل الملف. تبقى TLS عند ingress، وسياسات شبكة الإنتاج، وصلاحيات RabbitMQ، والنسخ الاحتياطية والرصد إعدادات فعلية تحتاج تنفيذًا واختبارًا. الوسيط الواحد في المرجع نقطة اعتماد واحدة؛ طوابير quorum على عقدة واحدة لا توفر توافرًا عاليًا للنظام.

## المهاجرات والبيانات

يشغل Compose الأمر `node dist/services/<name>/index.mts --migrate-only` وينتظر الرمز 0 قبل تشغيل الخدمة. تبقى `AUTO_MIGRATE=false` حتى تكون الخطوة صريحة. الجداول والمهاجرات ملك للخدمة وتضمّن في حزمة البناء. لا تعمل مهاجرات خدمة بحساب خدمة أخرى.

يعمل init script الخاص بـPostgreSQL مرة واحدة مع volume جديدة. تغيير `.env` لاحقًا لا يغير كلمات مرور الأدوار. تدويرها إجراء منظم داخل قاعدة البيانات، يليه تحديث ملف الاتصال وإعادة تشغيل المستهلك. يحتفظ RabbitMQ بتهيئته في volume أيضًا؛ لا يستخدم حذفها حلًا تلقائيًا لاختلاف كلمة المرور.

تحتاج migration إنتاجية إلى نسخة احتياطية مجربة، ومراجعة أثرها، وخطة توافق مع نسخة الخدمة الحالية. الرجوع إلى image قديمة لا يعكس تغييرات schema تلقائيًا. تختبر الترقية على قاعدة فارغة وقاعدة تحتوي بيانات، مع التأكد من أنها لا تمس بيانات نطاق آخر.

## الاستعداد والرصد

- `/health` يثبت حياة العملية. `/ready` في الخدمة يراجع قاعدة البيانات واتصال broker. تبقى HTTP حية أثناء إعادة اتصال نقل الأحداث.
- `/ready` في Gateway لا يجمع حالة كل upstream؛ تفحص الخدمات منفردة.
- تراقب outbox المتأخرة، وطوابير retry/dead، وتقدم fulfillment، ومدة الطلبات وأخطاءها. قبول العقد محليًا لا يعني إنشاء المشروع والفواتير في اللحظة نفسها.
- تربط correlation/request IDs السجلات. لا يسجل Bearer token أو URI يحتوي كلمة مرور.
- smoke المخصص للقراءة يراجع الهوية والقراءات فقط. انقطاع RabbitMQ وإعادة تسليم الأحداث يحتاجان وسيطًا حيًا.

لم تضف الحزمة تطبيق Kubernetes. الأولوية لتشغيل Compose والتحقق منه، ثم تحديد probes والموارد والتوسعة حسب قياسات التشغيل.
