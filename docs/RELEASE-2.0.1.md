# تصحيح التشغيل 2.0.1 — Windows والبناء والمزامنة

هذا إصدار صيانة مبني على سجلات Windows المرسلة في 13 نوفمبر 2026. تفاصيل كل رسالة وأوامر PowerShell في [تقرير التشخيص والحلول](WINDOWS-TROUBLESHOOTING-2.0.1.md)، وخطوات التثبيت الجديد في [دليل Windows](LOCAL-DEVELOPMENT-WINDOWS.md).

## ما تغير ولماذا

| العيب                                                                      | التصحيح                                                                                                                          |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| نسخ `config.js` يستدعي `chmod` ضمن `fs.cp` ثم يفشل على الجهاز المبلغ عنه   | نسخ محتوى الملفات دون نقل صلاحيات المصدر، في جميع عمليات نسخ الواجهات والوثائق                                                   |
| فاحص الحدود يتجاهل `tsconfig` عندما تختلف فواصل المسار على Windows         | تحقق من احتواء المسارات بواسطة `path.relative`، مع إبقاء الاختبار الأصلي وإضافة حالات Windows واسم مستعار يتصادم مع اعتماد خارجي |
| نجاح Capacitor sync بعد توقف بناء المندوب في منتصفه                        | سجل نجاح نهائي بعد اكتمال بناء التطبيقات الثلاثة؛ بصمات مدخلات ومخرجات يراجعها `mobile:sync` قبل تشغيل Capacitor                 |
| ثلاث رسائل `ENOENT` توحي بأعطال منفصلة عند تشغيل الاختبارات دون بناء مكتمل | حاجز سابق للاختبارات يشرح الحاجة إلى إعادة بناء ناجحة ويمنع اختبار مخرجات قديمة                                                  |
| تصدير صور الخدمة والمهاجر إلى الوسم نفسه بالتوازي                          | ثمانية منتجين فريدين للصور؛ المهاجرون السبعة يعيدون استخدام صورة المجال دون بناء مكرر أو سحب من سجل خارجي                        |
| ثغرة متوسطة في `fflate@0.8.2`                                              | تحديث محدود إلى `0.8.3` مع تحديث lockfile؛ لا تحديث شامل قسري للاعتماديات                                                        |
| تحذير سكربت esbuild في npm 11.19                                           | إذن خاص بـ `esbuild@0.28.2` داخل manifest، دون إذن شامل لبقية الحزم                                                              |
| فحص التنسيق يشمل صفحات preview المجمعة                                     | استثناء ملفات العرض المولدة؛ تثبيت LF لمصدر Git مع إبقاء ملفات BAT على CRLF                                                      |
| Java ومسارات الدليل كانت أمثلة قابلة للنسخ الخاطئ                          | اكتشاف JDK 21 وفحص أدواته، مسار المشروع الفعلي، توقف صريح عند فشل أوامر native، و`try/finally` للبناء                            |
| اختبارات CI كانت على Ubuntu فقط                                            | وظيفة Windows بالإصدارات التي أرسلها المستخدم: Node 24.21.0 وnpm 11.19.0                                                         |

رقم إصدار الجذر `2.0.1`، وحزم workspaces الداخلية تبقى `2.0.0` مع مراجعها المتوافقة. لم تتغير قواعد الأعمال أو CSS أو مكونات الواجهة في هذا الإصدار.

## التحقق المنفذ

بيئة التنفيذ المحلية Linux وNode 24.22.1. شُغّل فحص المصدر على npm 11.9.0، ثم استُخدم npm 11.19.0 في النسخة النظيفة وتدقيق الاعتماديات. تفاصيل النتائج الآلية في `docs/evidence/windows-fix-2.0.1.json`.

| الفحص                   | النتيجة ونطاقها                                                                                                        |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `npm run verify`        | نجاح TypeScript والحدود وبناء التطبيقات والخدمات والاختبارات وparity وregression                                       |
| اختبارات Node           | 65 اختبارًا: 64 ناجحًا، صفر فشل، واختبار PostgreSQL مشروط واحد متخطى                                                   |
| اختبارات فاحص الحدود    | 26 ناجحة، بينها الاختبار الذي فشل لدى المستخدم وحالات `path.win32`                                                     |
| حزم HTML الفعلية        | ثلاثة اختبارات بدء ناجحة دون اعتماد على ملفات أصول خارجية                                                              |
| توافق الواجهات          | 64/64 مسارًا و9/9 أصول تصميم؛ 122 معالج إجراء مسجلًا، وصفر أخطاء runtime في parity                                     |
| حالات السلوك            | 137 ناجحة في سبع مجموعات: 16 + 16 + 16 + 17 + 14 + 40 + 18                                                             |
| منع رجوع خلل الصلاحيات  | بناء التطبيقات الثلاثة نجح مع محاكاة رفض `fs.cp` و`chmod` بـ EPERM                                                     |
| أداة التصحيح            | فحص التعارضات قبل التعديل، حفظ الأصل، قبول CRLF، إعادة التطبيق دون تكرار، ورفض تلف الحزمة والكتابة خارج النطاق         |
| حزمة التصحيح الفعلية    | استُخرج ZIP الإصدار 2.0.0 الأصلي؛ نجح الفحص والتطبيق وإعادة التطبيق دون تغيير إضافي                                    |
| npm audit               | صفر ثغرات مُبلغ عنها وقت الفحص بعد تحديث `fflate`                                                                      |
| سكربتات تثبيت npm 11.19 | `No packages with unreviewed install scripts`                                                                          |
| Compose                 | تحليل YAML يثبت ثمانية أسماء صور فريدة وسبعة مهاجرين يستخدمون صور مجالاتهم، مع الحفاظ على شروط البدء والشبكات وvolumes |

في النسخة المستقلة المستخرجة من الحزمة القديمة بعد تطبيق التصحيح، نجح `npm ci` بإضافة 222 حزمة، ثم `verify` و`check:format` باستخدام npm 11.19.0. نجحت مزامنة Android للتطبيقين: ثلاثة ملحقات للمندوب واثنان للعميل. نجح أيضًا إعادة إنتاج ZIP من هذه النسخة. المزامنة هنا تنسخ الأصول والملحقات؛ لم تشغّل Gradle.

لا تعني الأعداد المختلفة اختبار كل احتمال ممكن. اختبار PostgreSQL المنفصل من الإصدار السابق له دليله السابق؛ لم يُعد هنا لأن التغيير لم يمس منطق الخدمات أو تخزينها. نتائج Docker وreadiness والعزل التي أرسلها المستخدم مذكورة بوصفها نتائج جهازه، لا تشغيلًا من بيئة التصحيح.

## حدود التحقق

- لم تتوفر جلسة Windows فعلية؛ تشغيل `path.win32` ومحاكاة EPERM ليسا بديلًا عن ذلك. وظيفة CI أُضيفت إلى المصدر، ولم تُسجل هذه الجولة تشغيل GitHub Actions فعليًا.
- لم يُشغل Docker أو RabbitMQ حي في بيئة التصحيح. يختبر المستخدم أوامر Compose الجديدة على بيئته التي نجحت فيها الفحوص السابقة.
- نسخ أصول Android عبر Capacitor لا يُعد بناء APK. يلزم نجاح Gradle باستخدام JDK 21 وSDK المطلوب ثم اختبار الجهاز أو المحاكي.
- لم يُبنَ APK أو IPA، ولم يُختبر GPS على جهاز فعلي في هذه الجولة.
- الواجهات ما زالت تستخدم مهايئ البيانات التجريبية. ربط جميع أوامرها بالخدمات مستقل عن معالجة أخطاء أدوات التشغيل؛ الحالة مفصلة في `MIGRATION-MATRIX.md`.

## التحديث

الحزمة `AtlasCRM-Enterprise-2.0.1-Hotfix.zip` مخصصة للنسخة الحالية. أداة `apply.mjs` تتحقق من بصمات المصدر الأصلي قبل استبداله وتحفظ نسخة احتياطية؛ تتوقف عند تعديل محلي يحتاج إلى دمج. الحزمة الكاملة `AtlasCRM-Enterprise-2.0.1.zip` مناسبة لنسخة جديدة.

بعد التحديث نفذ `npm.cmd ci` ثم `npm.cmd run verify`. يتضمن دليل التشخيص تنظيف مخرجات البناء المتوقفة وأوامر تشغيل الواجهات والخدمات وضبط Java وبناء الهاتف بالترتيب.
