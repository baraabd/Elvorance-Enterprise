# Production quality execution contract — S01

Version: 1. Scope: `baraabd/Elvorance-Enterprise`, all three applications, shared packages, gateway and seven domain services.

## Authority and acceptance language

This contract implements the requirements in the Sprint 1 execution request. No separate accompanying contract attachment was available in the execution context or Project-file search. Consequently this is an explicit, reviewable interpretation of that request, not a quotation of an unseen contract. A supplied stricter contract takes precedence through a reviewed change and a new complete run.

`PASS` means the named check executed successfully against the identified source. `FAIL` means an executed assertion failed. `BLOCKED` means evidence, a dependency, infrastructure, credentials, a runner, approval or a mandatory execution is missing, pending, cancelled, skipped, stale or unverifiable. Aggregated acceptance is fail-closed: either PASS or BLOCKED with reasons. Neither a green historical check nor an exit-zero wrapper establishes current feature completeness. “DONE”, production-ready, store-ready, zero vulnerabilities and 100% coverage must not be asserted without appropriate evidence.

## Source reconciliation

Read live main, PR metadata, actual head commits, comparison/merge base and checks before selecting a baseline. Descriptions, audit documents and source-export filenames are not authoritative heads. Preserve valid work on a new review branch. Do not merge, force-push or change deployment environments as a side effect of this sprint. Carry the single PR #3 release-gate document unchanged; retain PR #4 implementations without representing their prior runs as this sprint's results. `source-reconciliation.json` records the input observations.

The final test source is the actual PR head, not an implicit GitHub merge checkout. Every evidence record identifies the full source SHA, Git tree, lockfile SHA-256, repository, run ID, attempt and run URL. A merge-group run tests the merge-group SHA separately. Source archives are compared to tracked Git blobs, with declared Git line-ending attributes and the existing regenerated parity report explicitly distinguished. Generated preview HTML is not original source.

## Inventory and debt

Generate `feature-matrix.json` from source ASTs, actual application registrations, actual Fastify registrations and shared live-workspace sections. Include local/demo and server modes separately. Include forms, handlers, controls, search/filter/export call sites, failure handlers, permissions, account/configuration surfaces, events and timers. Never use an old count as an upper bound. Each entry has a stable ID, source location/hash, technical owner, endpoint list, authorization and persistence/event evidence or explicit uncertainty, implementation status, proposed sprint and existing/planned test IDs. A planned ID is not an existing or passing test. Only inspected, genuinely presentational actions may be marked presentation-only, with a reason.

`npm run inventory:check` regenerates in memory, compares every generated inventory, checks actual/static route equality and checks HTTP contracts in both directions. An unresolved registration or unreviewed drift fails. Source manifests cover source outside recognized syntax, but do not imply semantic review of every reachable branch. Static controls and implicit/dynamic behavior that require review remain explicit inventory limitations, not fabricated endpoint mappings.

The accepted `debt-baseline.json` is a per-item non-regression limit, not a blanket allowance. New suppressions, explicit `any`, test-only/skip/todo declarations and excluded TypeScript files fail even when another item is removed. Initial baseline creation refuses to overwrite an existing baseline. Reductions are encouraged; any reviewed exception requires a rationale, owner, expiry and independent approval, never automatic regeneration to make CI green. Legacy debt remains visible. No new S01 source uses type-check suppression. `workflow-gap-baseline.json` independently prevents new missing contract/integration/E2E links or loss of existing links, even when a different gap is closed. `feature-test-links.json` accepts only actual catalog IDs with reviewed rationale; `coverage-gaps.json` distinguishes missing links from missing frozen-parity cases.

## Mandatory FULL-CI

The required aggregate check is **FULL-CI**, defined in `.github/workflows/full-ci.yml`. It runs on every pull request without path exclusions, main/relevant sprint pushes, merge groups and manual invocation. It always evaluates all five dependency jobs, including when they fail or skip. Each of these eight evidence gates must exist and pass for the same source, run and attempt:

| Gate              | Required execution                                                                                                                                                                                                                                                                                        |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `quality-linux`   | Immutable install; inventory/debt; strict types; boundaries; legacy audit report; all application/service builds; every existing discovered Node test including real PostgreSQL; parity; all seven regression suites; standalone merged suites; example build; formatting; source package and blob proof. |
| `quality-windows` | Windows repair-script parse, immutable install and the same complete quality runner.                                                                                                                                                                                                                      |
| `native-linux`    | Existing Linux native-verification foundation, using the same complete quality runner.                                                                                                                                                                                                                    |
| `native-android`  | Existing native preparation, lint, unit tests, unsigned bundle and emulator instrumentation. Both unit and emulator JUnit totals must be present.                                                                                                                                                         |
| `native-ios`      | Existing iPhone-simulator suite, successful Xcode execution and machine-readable xcresult totals. An unknown result format blocks.                                                                                                                                                                        |
| `runtime`         | Real isolated Compose gateway, seven services, PostgreSQL/RabbitMQ, cross-service database-denial check and complete existing synthetic distributed journey.                                                                                                                                              |
| `identity`        | Real disposable loopback HTTPS Keycloak: existing bootstrap, PKCE, signed ID-token/claims, admin-only attributes, refresh rotation/replay and logout suite.                                                                                                                                               |
| `security`        | Live dependency-advisory audit and high-confidence tracked-source secret scan. High/critical advisories or unavailable advisory results block. Scanner limitations are reported.                                                                                                                          |

All Node suites report TAP totals. An unexecuted test is not a pass. Linux must run the real PostgreSQL test, with zero skips. Windows and native-Linux may each report exactly the existing single PostgreSQL wrapper skip because that identical database suite is mandatory on Linux; the runner verifies the exact skipped test name and the aggregate still requires Linux. This is a complementary-platform allocation, not a waiver of the database gate. All other skips, todos, cancellations, missing totals and failures block. Native suites allow no skips. Repeated suites across platforms and standalone runs are reported separately, not added into a misleading unique-workflow count.

`audit:migration:report` measures legacy migration debt; its exit-zero does not pass strict migration acceptance. `audit:migration --strict` remains a separate known-failing production acceptance criterion while the baseline contains debt. Signed store-release workflows remain manual, secret/approval gated and explicitly outside unsigned S01 verification. Not running a store release cannot be described as store approval.

## Evidence and reruns

Upload measured logs/reports and an evidence manifest, with each file's size and SHA-256. Evidence archives use run-attempt-qualified names. The aggregate checks GitHub artifact IDs, immutable archive digests, positive sizes, non-expiration, source linkage and the bytes of every downloaded evidence file. It also requires both source archives. Local output cannot attest GitHub FULL-CI. No unrelated commit, old attempt or historical audit report may satisfy a missing gate.

`FULL-CI.json` and its SHA-256 sidecar are produced by the final aggregate, not committed to the source they describe; this avoids a self-referential final-SHA claim. GitHub's artifact ID/digest for that aggregate is the outer immutable link. Evidence retention is bounded, not permanent archival: preserve accepted evidence in an approved retention store before GitHub expiry. Such a store is currently an external blocker.

After **any** source, workflow, baseline or documentation change, run **all** gates again on the new final commit. Rerunning only failed jobs with a new attempt does not satisfy this contract, because evidence from different attempts cannot be combined. Report exact final SHA/tree, run/attempt URL, per-gate totals/skips and artifact digests. Pending mandatory jobs mean BLOCKED. Never delete or weaken a test simply to obtain green status.

## Security, infrastructure and production boundaries

Use fresh disposable CI credentials only for isolated CI fixtures. Never invent hosted-provider credentials or imply a fixture implements an absent integration. Keep tokens, signing material, environment values and identity test credentials out of logs and artifacts. Unavailable hosted identity, payment, mail/SMS/push, maps, observability, backups or signing dependencies are blockers with owners/evidence requirements. A platform project, staged patch, environment-variable name, mocked response, simulator or local container is not a deployed integration.

Repository protection must require `FULL-CI` and independent review, with administrative bypass controlled. A CODEOWNERS file and a workflow do not themselves enable protection. The observed main branch was unprotected; `required-checks.json` is a proposed administrator configuration, not evidence it is enforced. Domain ownership and independent reviewer assignments remain explicit where unassigned.

Capacity, recovery, availability and coverage values in `budgets.json` are **proposed targets**, never measured achievements. Release approval additionally needs hosted end-to-end acceptance, threat remediation, restore/load evidence, physical-device tests, operational ownership and required external integrations. S01 CI success does not override these blockers.
