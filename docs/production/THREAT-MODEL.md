# S01 threat-model baseline

Status: **source-level baseline, not a penetration-test result or production security approval**.

Assets: tenant/customer/contact data, quote/contract decisions, invoices/payment records, location/consent, messages/support, credentials/refresh tokens, signing keys, event envelopes, backups and CI/source artifacts. Actors: unauthenticated attacker, authenticated wrong-role/wrong-tenant/wrong-owner user, compromised browser/device, compromised service or dependency, malicious event producer and malicious repository contributor.

Trust boundaries and source-backed data edges are in `data-flow-inventory.json`. User input crosses client-to-gateway, gateway-to-domain, domain-to-owned-database, outbox-to-broker/inbox and native-to-OS/identity-provider boundaries. Demo/local state is never trusted production storage.

Threats are not closed by a source reference. Existing test families are candidates until the exact final CI report supplies execution evidence. High/critical dependency-audit findings block FULL-CI; the narrow source secret-pattern scanner does not establish full secret detection or vulnerability absence. A malicious PR can edit its own workflow, so protected reviews/CODEOWNERS and branch rules are necessary in addition to self-generated artifacts.

No real provider credentials, customer data or signing material are needed for S01. CI creates only short-lived synthetic local test identities and removes its own disposable containers. Do not run destructive restore/rotation tests on production.
