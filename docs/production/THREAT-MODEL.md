# Threat-model baseline — S01

Status: baseline for review; not a penetration-test report or security certification. Scope includes all three apps in demo/server modes, native bridges, gateway, seven services, owned databases, broker, identity provider, CI and source/evidence packaging. Source references below are review anchors; passing a static check is not proof of exploit resistance.

## Assets and trust boundaries

Protect tenant/customer records, commercial quotes/contracts/discounts, messages, location history, account/profile data, access/refresh tokens, signing material, service credentials, audit/event history and release/evidence integrity. Untrusted boundaries include UI input to service validation, device/browser to identity and gateway, gateway to independently authorizing services, service-to-service ownership calls, database roles/RLS, outbox-to-broker-to-consumer, CI input code/dependencies and external delivery providers.

## Risk treatment

Open items are blockers for the affected production workflow. Severity and residual-risk acceptance require a named reviewer; no risk has been silently accepted by generating this document. Synthetic data and disposable local CI credentials must never be reused in hosted environments. Existing successful tests are evidence only for their actual scenario/source/run. S01 establishes traceability and non-regression, not blanket remediation of every threat.

Before changing a threat to mitigated, record the exact feature IDs, enforcement locations, existing executable test IDs, immutable run evidence and owner approval. A test's presence in `test-catalog.json` is insufficient. The next sprint starts with TM-01, TM-02, TM-04, TM-08 and TM-12 and account/permission negative cases.
