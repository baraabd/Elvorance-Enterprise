# ADR-003 — outbox و inbox واتساق يظهر للمستخدم

الحالة: معتمد في البنية المرجعية 2.0.

## القرار

يحفظ المنتج حدث الأعمال في outbox مع السجل المحلي في معاملة واحدة. ينشر worker الحدث إلى topic exchange باسم `atlas.events`. تملك الخدمات طوابير quorum بأسماء `atlas.<service>.v1` ومسارات retry/dead. يستخدم المستهلك inbox وقيود المفاتيح التجارية داخل معاملته المحلية قبل إثبات المعالجة.

لا ندعي exactly-once في النقل؛ التصميم يتحمل التسليم المتكرر. يحتفظ العقد المعتمد بسجل fulfillment بحالة pending حتى تصل أحداث إنشاء المشروع والفواتير. تعطل RabbitMQ لا يلغي معاملة سبق أن حُفظت، ولا يجب تحويل واجهة المستخدم فورًا إلى نجاح جميع الخدمات.

## النتائج

تتطلب البوابة التشغيلية اختبار الانقطاع وإعادة التشغيل وإعادة تسليم الحدث، لا اختبار handler في الذاكرة فقط. dead-letter حالة تحتاج تشخيصًا وقرار إعادة تشغيل بعد إصلاح السبب؛ لا يُحذف الحدث بصمت. correlationId يربط السجلات دون طباعة bearer token أو بيانات اتصال قاعدة البيانات.

تحتاج التغييرات الكاسرة في payload إلى إصدار حدث جديد وخطة تعايش للمستهلكين. تبقى تغيرات API المتوافقة تحت `/v1`؛ تضاف نسخة جديدة عند كسر العقد. انظر `API-CONTRACTS.md`.
