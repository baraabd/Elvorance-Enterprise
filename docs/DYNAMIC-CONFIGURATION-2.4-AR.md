# AtlasCRM — إعدادات الأسئلة والخدمات الديناميكية (مرجع الدمج 2.4)

## مصدر النسخة

هذا **تعديل مرجعي على المصدر المتاح للإصدار 2.0.1**، وليس إعادة بناء مثبتة فوق ملفات الإصدار 2.3 الحديثة. لا تستبدل نسختك الحالية بالمصدر المرجعي إذا كانت تحتوي تعديلات أحدث. استخدم ملف `AtlasCRM-Dynamic-Configuration-2.4.patch` مع `git apply --check` ثم ادمج التعارضات يدويًا.

## التغيير المنفذ

- لوحة الإدارة: صفحة **استبيانات ومحتوى المبيعات** في المزيد/الإعدادات؛ إضافة وتعديل وأرشفة أنواع الأنشطة، الأسئلة، الخيارات، الإلزام، ترتيب السؤال ونوع إجابته (اختيار واحد، متعدد، نص، رقم)، والخدمات والأسعار والنطاق ووسوم التوصية.
- المندوب: مسار **استبيان العميل** داخل الزيارة: النشاط → التحديات → النتائج → الخدمات. لا يفتح إعداد العرض قبل إكمال الأسئلة المطلوبة. تحفظ المراجعة نسخة من نص الأسئلة والخيارات والخدمات وإصدار التعريف مع الزيارة.
- العميل: **احتياجات منشأتك** تعرض أسئلة ونطاقًا متغيرين حسب النشاط، وتحفظ الإجابات بنسخة التعريف.
- معايير التحقق: الحقول المطلوبة، صحة الاختيارات، عدم قبول خدمات مؤرشفة، شرح «أخرى»، حدود طول النص، القيم الرقمية (بما فيها min/max)، الأسعار، الهاتف والبريد. الواجهة تفحص أوليًا، وخدمة CRM تفحص تعريف البيانات عند نشره.
- ملخصات العميل: المشاريع الجارية، القرارات المطلوبة، والفواتير ذات الرصيد المتبقي أصبحت بطاقات تنقل مباشرة إلى قوائمها المفلترة.
- ملخصات الإدارة: المندوبون، الزيارات المكتملة، الموافقات والمهام تفتح قوائمها. زيارة مكتملة تعرض اسم العميل والمندوب والتاريخ.

## مصدر البيانات والتزامن

في **وضع التجربة المحلية** (الإعداد الافتراضي) تُحفظ البيانات عبر `localStorage` داخل الأصل (origin) نفسه، وتتشاركها التطبيقات المفتوحة على ذلك الأصل فقط، لا بين الهواتف المختلفة.

أُضيفت حدود خدمة `CRM` التالية، محفوظة لكل شركة في PostgreSQL مع Row-Level Security:

- `GET /v1/crm/configuration` : قراءة تعريف الأسئلة والأنشطة والخدمات، وصلاحية القراءة لأي عضو مصادق داخل الشركة.
- `PUT /v1/crm/configuration` : نشر تعريف متحقق منه؛ يتطلب دور `admin`، وإصدارًا متوقعًا `expectedVersion`، و`Idempotency-Key`. يتغير الإصدار عند النشر ويظهر عند القراءة.

تنشئ المهاجرة رقم 2 جدول `configuration` مع RLS وقيد سجل واحد لكل شركة، دون تغيير محتوى المهاجرة رقم 1 المسجلة سابقًا.

**لتفعيل قراءة الإعدادات بين أجهزة حقيقية**: شغّل خدمات Docker، وعيّن `configurationApiBaseUrl` إلى أصل Gateway عبر HTTPS، ووفر `window.ATLAS_AUTH.getAccessToken()` من نظام تسجيل دخول حقيقي لكل دور. `packages/questionnaire/src/sync.js` يجلب الإصدار عند البدء، ويعيد القراءة دوريًا عندما تكون الواجهة ظاهرة، ويرسل تعديلات الإدارة إلى الخادم. لم تُربط المصادقة المستقلة للتطبيقات أو بقية سجلات الأعمال في هذه النسخة المرجعية، ولذلك لا تُعتبر جاهزة لتجربة إنتاج متعددة المستخدمين.

## حفظ التاريخ

كل استبيان محفوظ يتضمن `configRevision` ونسخة labels/options عند وقت الإدخال؛ تعديل نص السؤال أو سعر الخدمة مستقبلًا لا يغيّر محتوى الاتفاقيات التاريخية.

## السلامة والموافقة

- الترشيحات الحالية قواعد واضحة قابلة لتعديل وسومها من الإدارة، وليست نموذج ذكاء اصطناعي أو ضمانًا لزيادة المبيعات.
- الأرشفة تمنع الإضافة الجديدة دون حذف محتوى الاستبيانات السابقة.
- لا تضع بيانات صحية شخصية أو سرية ضمن حقول النشاط والإجابات؛ مع العيادات يُفضّل تسجيل عمليات المنشأة فقط.

## التشغيل على Windows (في نسخة مرجعية مستقلة)

```powershell
Set-Location 'C:\Mobile_Apps\AtlasCRM-Enterprise'
node --version # >=24.15 <25
npm.cmd ci
npm.cmd run check:types
npm.cmd run check:boundaries
npm.cmd run build:apps
node --test tests/questionnaire/dynamic-form.test.mjs tests/validation/numeric-fields.test.mjs
npm.cmd run dev
```

للدخول إلى صفحة الإدارة استخدم `http://localhost:4173/admin-web/` ثم المزيد → الاستبيانات والخدمات. في تطبيق المندوب افتح الزيارة الجارية ثم استبيان العميل؛ في تطبيق العميل افتح الخدمات ثم «احتياجات منشأتك».

يمكن تجربة نموذج HTML المستقل دون تثبيت اعتماديات المشروع عبر فتح `AtlasCRM-Dynamic-Configuration-Preview.html`. في حال منع المتصفح التخزين عند `file://`، شغّله من خادم محلي:

```powershell
python -m http.server 8765
```

## الاختبارات وحدود التحقق

- `node --test tests/questionnaire/dynamic-form.test.mjs tests/validation/numeric-fields.test.mjs`: **20 حالة ناجحة / 0 فشل** في البيئة الحالية.
- فحص بناء الجملة في ملفات JS المتغيرة: نجح.
- فحص صياغة TypeScript للخدمة والمهاجرة: نجح دون أخطاء parsing.
- **لم يكتمل** `npm ci`, و`npm run verify`, واختبار PostgreSQL/Android/Chromium: البيئة تعمل على Node 22 لا Node 24 وذاكرة حزم npm غير مكتملة، كما يمنع المتصفح الوصول إلى الملفات والخادم المحلي. يجب إعادة الفحوص في جهازك باستخدام Node 24 وPostgreSQL.
- فحص التطابق البصري مع تصميم الإصدار 2.3 غير مثبت؛ مصدر الإصدار 2.3 غير متوفر هنا. الدمج يجب أن يكون إضافيًا على كودك الأحدث.

## كيف تُدمج بأمان؟

راجع الحزمة الجديدة و`AtlasCRM-Dynamic-Configuration-2.4.patch` قبل التطبيق. الأمر `git apply --check` لا يغيّر الملفات:

```powershell
Set-Location 'C:\Mobile_Apps\AtlasCRM-Enterprise'
git apply --check 'C:\path\to\AtlasCRM-Dynamic-Configuration-2.4.patch'
# إذا نجح فقط:
git apply 'C:\path\to\AtlasCRM-Dynamic-Configuration-2.4.patch'
```

أُنشئ ملف التصحيح بالمقارنة مع 2.0.1، وقد يُظهر تعارضات على 2.3. إذا فشل الفحص فلا تستخدم `--force` ولا تستبدل ملفات التطبيقات؛ ادمج الوحدات المطلوبة يدويًا مع الحفاظ على إصدارك الأحدث والاختبارات الأصلية.
