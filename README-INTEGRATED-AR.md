# Elvorance Enterprise — حزمة مصدر مجمعة (2.4.1)

**هذه حزمة مشروع كاملة قابلة للفك والتطوير، وليست ملف تصحيح منفردًا.** تحتوي `apps/` و`services/` و`packages/` و`infra/` و`tooling/` و`tests/` و`examples/`.

## مصدر الحزمة وحدود المطابقة

أُنشئت انطلاقًا من **Elvorance-Dynamic-Configuration-2.4-Reference.zip** الذي بُني أصلًا فوق إصدار 2.0.1، ثم أُدخلت فيه التعديلات البرمجية المتاحة من حزم بطاقات المندوب ومسار البيع الفوري ومنطق الخصم والدفعات. **ملفات المصدر الأصلية الكاملة لإصدار 2.3 المنشور ليست ضمن المدخلات المتاحة**؛ لذلك لا يمكن تأكيد التطابق الحرفي لكل شاشة أو سلوك مع النسخة المنشورة. يوصى باستخدام هذه الحزمة في نسخة تطوير مستقلة، وعدم نسخها فوق مشروع حديث يحتفظ بتعديلات إضافية لم تراجع.

## ما تم دمجه في تطبيقات المشروع

- `apps/rep-mobile`: بطاقات الأداء التفاعلية (المهام المفتوحة، الفرص قيد العمل، الفرص المكتسبة، العروض المرسلة)، مع فلاتر القائمة والسجلات؛ خيار نتيجة «العميل موافق ومستعد لبدء التنفيذ» مع منع تسجيل موافقة أو تحصيل بالنيابة عن العميل؛ محرر السعر والخصم بالدولار أو النسبة وجدول دفعات متوازن وحد أدنى للدفعة الأولى 20%.
- `apps/client-mobile`: الاستبيان الديناميكي المتاح من مصدر 2.4 وربطه بالأنشطة والأسئلة المعتمدة، إلى جانب دورة الموافقة على العرض والعقد الموجودة في المصدر المرجعي. لا تعد نية الدفع إيصالًا رسميًا.
- `apps/admin-web`: إدارة الأنشطة والأسئلة والخيارات والخدمات من المصدر المرجعي 2.4، وبطاقات مؤشرات الإدارة والعميل التي تفتح قوائم مفلترة.
- `packages/questionnaire`: تعريف الأسئلة والاختيارات والتحقق ومزامنة الإعدادات؛ قابل للنشر من مدير مخول في CRM.
- `packages/app-runtime/src/finance.js`: حساب مالي مستقل بالسنتات مع اختبار مبالغ الخصم والدفعات والفروقات.
- `services/`: بوابة API والخدمات المستقلة للهوية وCRM والمبيعات والتنفيذ والفوترة والتتبع والمراسلات.
- `examples/instant-close`: نموذج مستقل للتجربة والتوثيق يوضح قرار العميل والموافقة على العقد والتحصيل بواسطة المالية؛ **لا يحق للمندوب استعماله لإثبات دفع حقيقي**.

## التشغيل المحلي على Windows

ضع الحزمة في مجلد تطوير **جديد** لا يحمل تعديلًا محليًا غير محفوظ، وافتح PowerShell فيه:

```powershell
node --version      # Node 24.15 أو أحدث ضمن سلسلة 24
npm.cmd --version   # npm 11
npm.cmd ci
npm.cmd run test:merged
npm.cmd run build:apps
npm.cmd run dev
```

تُفتح الصفحة الرئيسية عادة على `http://127.0.0.1:4173`، ويمكن تشغيل الخدمات من `infra/compose` بعد مراجعة ملفات `.env.example`:

```powershell
node .\infra\compose\init-env.mts
npm.cmd run infra:up
node .\infra\compose\smoke.mts
```

احتفظ بملف `.env` الفعلي خارج ZIP. لا تشغل النسخة على قاعدة إنتاج دون مراجعة ترحيلات البيانات والهوية والصلاحيات.

## نتائج التحقق من هذه الحزمة

- اختبار مباشر لقواعد الاستبيان والتحقق والبطاقات والخصم والدفعات ومحاكاة البيع الفوري: **53/53 ناجح** في Node 22 المتاح للفحص. هذه اختبارات منطقية، وليست شهادة نشر إنتاجي.
- تحققت صياغة الملفات البرمجية المحددة وفُحص مصدر التقنيات المشتركة.
- **لم يُنفذ بناء جميع التطبيقات على Node 24، ولم تُجر اختبارات Chromium وAndroid وPostgreSQL الحي في هذه الجلسة**. ينبغي تشغيل `npm run verify` و`npm run build:apps` على جهاز التطوير قبل النشر.

## حالة الترابط بين الأجهزة

وضع المعاينة المحلي يُبقي بعض العمليات داخل `localStorage`. التعديل على خدمة CRM يدعم نشر تعريف الأسئلة المشترك عند إعداد هوية وصلاحيات حقيقية وتشغيل API. لا تعتبر البيانات المشتركة داخل متصفح واحد مزامنة إنتاجية بين هواتف مختلفة.

## ملف الخطوط

لم تُضمّن ملفات الخطوط الثنائية أو نسخ الخطوط المدمجة بصيغة base64 في الحزمة. يستخدم سكربت البناء خطوط النظام الاحتياطية، ويمكنك إضافة خطوط مرخّصة من مصدرك الخاص في بيئتك عند الحاجة. باقي ملفات التصميم والألوان والأيقونات باقية.
