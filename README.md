# Elvorance Enterprise · إلفورانس

ثلاثة تطبيقات مستقلة بنفس تصميم أطلس 2027، مع حزم مشتركة وخدمات خلفية مستقلة. هذه نسخة تأسيس هندسي قابلة للتطوير؛ لا تمثل اعتمادًا جاهزًا للنشر في شركة قبل إعداد الهوية والبنية التشغيلية واستكمال ربط كل أوامر الواجهة بالخدمات.

## تشغيل الواجهات الآن

المتطلبات: Node.js 24.x ابتداءً من 24.15، وnpm 11.x. يحتوي الإصدار 2.0.1 على تصحيح بناء Windows والمسارات ومزامنة ملفات الهاتف؛ راجع [تقرير الأخطاء وأوامر إصلاح Windows](docs/WINDOWS-TROUBLESHOOTING-2.0.1.md). في PowerShell استخدم `npm.cmd` بدل `npm` إذا كانت سياسة الجهاز تحظر `npm.ps1`.

```sh
npm ci
npm run dev
```

افتح `http://localhost:4173`. التطبيقات الثلاثة موجودة أيضًا منفردة:

```sh
npm run dev:rep
npm run dev:client
npm run dev:admin
```

افتح التطبيق من خادم HTTP المحلي، وليس بالنقر على ملفات المصدر. نسخ HTML المستقلة للتجربة تُنشأ داخل `dist` بعد `npm run build:apps`.

## ما نُقل وما أُضيف

| المسار                     | المسؤولية                                                              |
| -------------------------- | ---------------------------------------------------------------------- |
| `apps/rep-mobile`          | تطبيق المندوب: الزيارات والعملاء والفرص والعروض والمناطق والمتابعة     |
| `apps/client-mobile`       | تطبيق العميل: الخدمات والعروض والعقود والمشاريع والفواتير والدعم       |
| `apps/admin-web`           | لوحة الإدارة: الفريق والمناطق والمبيعات والموافقات والتنفيذ والإحصاءات |
| `packages/design-system`   | الألوان والمقاسات والخطوط وSVG وCSS المعتمد، من مصدر واحد              |
| `packages/ui`              | مكونات عرض قابلة للتركيب: الأزرار والحقول والعناوين والحالات البصرية   |
| `packages/app-runtime`     | التوجيه والواجهة العامة والنوافذ والأحداث وتنسيقات العرض               |
| `packages/demo-data`       | بيانات وهمية ومستودع المتصفح المحلي الصريح                             |
| `packages/api-client`      | نقل HTTP موحد، مصادقة، أخطاء، مهلة ومفاتيح منع التكرار                 |
| `packages/mobile-platform` | بوابة Capacitor للموقع والشبكة وحالة التطبيق والتنقل                   |
| `packages/contracts`       | عقود الرسائل وDTOs العامة، دون قواعد أعمال مشتركة بين الخدمات          |
| `packages/service-kit`     | مصادقة وHTTP ومعاملات وتخزين وعزل المستأجرين                           |
| `packages/events`          | إرسال الأحداث الموثوق وإزالة التكرار لدى المستهلكين                    |
| `services`                 | بوابة API وسبع خدمات نطاق مستقلة                                       |
| `infra`                    | صور Docker وCompose وتهيئة قواعد البيانات                              |
| `tests`                    | حدود الاستيراد وتوافق التصميم وتكامل حالات الأعمال                     |
| `docs`                     | شرح الحدود وملكية البيانات والتشغيل والترحيل والقرارات                 |

الشاشات الحالية أصبحت **32 feature modules و64 route و122 application handlers**. كل تطبيق يجمّع وحداته في `src/app.ts`؛ لا توجد نسخة كاملة جديدة من التطبيق داخل ملف واحد. أصبحت الوحدات بامتدادات TypeScript، لكن عددًا من ملفات الواجهات ما زال يحتوي على `@ts-nocheck`؛ لذلك لم تكتمل بعد مراجعة الأنواع في جميع الوحدات، ولم يتحقق التكامل الكامل مع خدمات API.

## فرق مهم عند التطوير

الواجهات المحفوظة تستخدم حاليًا `dataMode: "demo"` وتخزن بيانات التجربة في المتصفح. فصل الوحدات لا يحوّل هذه البيانات تلقائيًا إلى بيانات خادم. نسختا الهاتف لهما مخزن منفصل، ولا تتزامنان عبر `localStorage` بين جهازين. `dataMode: "server"` يُرفض صراحة إلى أن تُربط أوامر كل feature بواجهات الخدمة؛ لا توجد مزامنة وهمية لكامل JSON.

الخلفية تحتوي مسارًا مرجعيًا مستقلًا قابلًا للتشغيل والاختبار: عميل ← زيارة ← عرض ← قبول العميل ← اعتماد العقد ← مشروع وفواتير عبر الأحداث. راجع مصفوفة الترحيل في `docs` لمعرفة الوحدات التي تحتاج ربطًا إضافيًا. الواجهات الحالية تحافظ على سلوك التجربة، بما فيه ملخص اتفاق الزيارة.

## تشغيل الخدمات

تحتاج Docker مع Compose. ابدأ بتوليد إعدادات تطوير محلية، ثم شغّل البنية:

```sh
node infra/compose/init-env.mts
npm run infra:up
```

راجع دليل التشغيل في `docs` لمعرفة الحصول على رمز تطوير واختبار المسار الخلفي. المنفذ `3000` هو بوابة API، والخدمات `3001` إلى `3007`. لكل خدمة قاعدة بيانات ودور خاصان؛ لا تقرأ خدمة جداول خدمة أخرى. في الإنتاج استخدم OIDC/JWKS، ومدير أسرار، وعناوين HTTPS، وسياسات الشبكة والنسخ الاحتياطي الخاصة ببيئتك.

```sh
npm run infra:down
```

هذا الأمر لا يحذف وحدات التخزين. لا تضف `--volumes` إلا إذا كنت تقصد حذف بيانات التطوير.

## تطبيقَا الموبايل

Capacitor يغلف نفس واجهات HTML/CSS/JavaScript. تطبيق المندوب وتطبيق العميل لهما App ID ومجلد Android ومجلد iOS مستقلان. للتحديث بعد تعديل الواجهات:

```sh
npm run build:apps
npm run mobile:sync
```

لفتح مشروع:

```sh
node tooling/scripts/mobile.mts open rep-mobile android
node tooling/scripts/mobile.mts open client-mobile ios
```

Android يحتاج Android Studio وSDK المناسبين. iOS يحتاج macOS وXcode. وجود المشروع الأصلي ومزامنة الويب لا يعني بناء APK/IPA أو اختباره على جهاز. مشاركة الموقع تحتاج موافقة المستخدم وعنوان خدمة HTTPS يمكن للهاتف الوصول إليه؛ `localhost` داخل الهاتف يشير إلى الهاتف نفسه. جسر الموقع الحالي مخصص للعمل في المقدمة، ولا يدعي تتبعًا مستمرًا في الخلفية.

## الجودة والتوسع

```sh
npm run verify
npm run check:format
```

الأول يفحص أنواع TypeScript وحدود الاستيراد، يبني التطبيقات والخدمات، يشغّل الاختبارات ويقارن الشاشات بالتصميم المرجعي. الثاني يتحقق من تنسيق المصدر. التقارير لا تعني إثبات صحة كل حالة ممكنة في الواقع أو اختبار جهاز فعلي؛ حدود التحقق مسجلة في الوثائق.

أضف feature داخل التطبيق المالك، واستخدم مكونات `@elvorance/ui` ورموز `@elvorance/design-system`. عند الحاجة إلى شكل إضافي، أضف variant واضحًا للمكون الموجود قبل نسخ القالب. المكونات الخاصة بنطاق معين تبقى في ذلك النطاق. لا تجعل حزمة UI مستودعًا لقواعد المبيعات أو الفوترة، ولا تستورد تطبيقًا داخل تطبيق آخر.

أضف أي تغيير API إلى الخدمة المالكة وعقدها المعلن، مع اختبار السلوك والانتقالات والصلاحيات. استخدم `expectedVersion` عند تعديل سجل ومفتاح `Idempotency-Key` واحدًا لنفس نية المستخدم. استهلاك الأحداث قابل للتكرار؛ المستهلك يزيل التكرار داخل معاملته. اقرأ ADRs قبل تغيير حدود خدمة أو نقل ملكية بيانات.

## الاتصال التجريبي المباشر بالـAPI

يمكن تجربة واجهات البيانات الحية المتوفرة حاليًا بشكل مستقل عن بيانات Demo عند ضبط `dataMode: 'server'` وتوفير مصادقة صحيحة. **هذه ليست ترحيلًا كاملًا لجميع الشاشات.** راجع [دليل الوضع المباشر](docs/LIVE-SERVER-MODE.md) وحدود الاختبارات قبل اعتماد التشغيل.
